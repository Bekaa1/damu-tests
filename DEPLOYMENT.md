# Развёртывание на VPS

Требуются Linux VPS, Docker Compose, домен с DNS на сервер и открытые 80/443. Внешние порты БД, Redis, Minio и API в production не публикуются. Caddy завершает HTTPS и направляет `/api/*` напрямую в NestJS. Для первой организации достаточно начать с 4 vCPU / 8 GB RAM и измерить фактическую нагрузку PDF; это стартовая конфигурация, не гарантия SLA.

1. Скопировать `.env.production.example` в `.env.production`. Установить домен, уникальные секреты и одинаковый пароль Postgres в `POSTGRES_PASSWORD` и `DATABASE_URL`. Пароль в URL должен быть URL-safe. Файл хранить с правами 600.
2. Собирать и запускать команды из корня проекта:

```sh
docker compose --env-file .env.production -f compose.production.yml build api
docker compose --env-file .env.production -f compose.production.yml up -d postgres redis minio
docker compose --env-file .env.production -f compose.production.yml run --rm api npm run db:migrate
docker compose --env-file .env.production -f compose.production.yml run --rm api npm run db:seed
```

3. Создать владельца через `scripts/provision-owner.ts`. `OWNER_EMAIL`, `OWNER_PASSWORD` (от 16 символов), `OWNER_NAME` передать через защищённое окружение, без секретов в аргументах командной строки. Скрипт не перезаписывает существующую учётную запись.

```sh
docker compose --env-file .env.production -f compose.production.yml run --rm -e OWNER_EMAIL -e OWNER_PASSWORD -e OWNER_NAME api npx tsx scripts/provision-owner.ts
docker compose --env-file .env.production -f compose.production.yml up -d
```

4. Первый вход требует смены пароля. Владелец создаёт организацию и получает одноразово показанный временный пароль администратора. Затем администратор создаёт эксперта, участников и кампанию. Перед назначением методики публикуются владельцем после утверждения.

   В production API отказывается запускаться с `DEMO_MODE=true` или с локальной демонстрационной организацией в базе. Используйте отдельную чистую БД, чтобы известные демонстрационные пароли никогда не попали в рабочую среду.
5. В панели платформы настроить OpenRouter: модель, ключ, список согласованных провайдеров, ZDR и версию промпта. Для запросов установлены потолки стоимости провайдера $20/M входных и выходных токенов, 6000 выходных токенов, до 30 KB JSON-запроса. Перед каждой попыткой в транзакции резервируется $1; при известной стоимости резерв заменяется фактической. При сетевой неопределённости резерв остаётся учтённым. Лимит организации — совокупный, не месячный. Дополнительно задайте бюджет ключа в OpenRouter.

## Эксплуатация

- Секрет `SETTINGS_ENCRYPTION_KEY` хранить отдельно от базы и включать в защищённый план восстановления. При его потере ключ OpenRouter придётся ввести заново. Он никогда не возвращается через GET API.
- `GET /api/health` проверяет соединение с БД. Логи контейнеров и историю AI контролировать средствами VPS. Очередь хранится в Redis AOF. Для расширения добавляются ресурсы и отдельные worker-процессы; PDF требует ограничения параллельности на периметре.
- `sh deploy/backup.sh` создаёт дамп Postgres и снимок частных файлов. Во время согласованного окна резервного копирования приостановить запись материалов, чтобы снимки были согласованы. Шифровать и отправлять копии в утверждённое резервное хранилище, настраивать расписание отдельно от приложения. Секреты не включать в открытые архивы.
- Проверять восстановление в отдельной среде: новая БД, `pg_restore` дампа, восстановление S3-тома, те же ключи шифрования, проверка входа и скачивания отчёта. Не использовать восстановление поверх работающей БД.
- Обновление: резервная копия, новая сборка, `db:migrate`, перезапуск API/web. Миграции содержат только добавление таблиц/полей. Публикация новой методики не изменяет завершённые попытки; перерасчёт создаёт отдельную запись.
- При временной недоступности OpenRouter тесты считаются синхронно на backend, AI можно запустить повторно из карточки сотрудника. На время длительного инцидента ключ можно убрать из окружения/заменить настройку модели; пользовательские результаты остаются в PostgreSQL.

Это подготовленная конфигурация развёртывания. Домен и VPS в текущей сессии не предоставлены; публичный запуск не выполнялся.
