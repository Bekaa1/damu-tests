# AssessFlow

Рабочая локальная версия SaaS для оценки сотрудников. Next.js / React / TypeScript, NestJS, PostgreSQL / Prisma, Redis / BullMQ, частное S3-хранилище и PDF через Playwright. Серьёзный корпоративный интерфейс: тёмная навигация, спокойные зелёные акценты, таблицы, понятные статусы и отдельный экран прохождения без лишних элементов.

## Запуск на этом компьютере

Откройте **http://localhost:3000** и войдите с нужной учётной записью.

| Роль          | Email                     | Пароль в локальном демо |
| ------------- | ------------------------- | ----------------------- |
| Администратор | admin@assessflow.local    | AssessFlow!2026         |
| Эксперт       | expert@assessflow.local   | AssessFlow!2026         |
| Сотрудник     | employee@assessflow.local | AssessFlow!2026         |
| Владелец      | owner@assessflow.local    | AssessFlow!2026         |

65 участников и их результаты вымышлены. В production демонстрационные пользователи не создаются.

Чистая установка (Node.js 22.12+, Docker):

```powershell
npm ci
node scripts/local-env.mjs
npm run infra:up
npm run setup
npx playwright install chromium
npm run dev
```

`local-env.mjs` создаёт `.env` с новым секретом только при отсутствии файла. Не перезаписывайте существующий секрет: он защищает сессии и, если отдельный ключ не задан, сохранённый ключ OpenRouter.

## Реализованные сценарии

- Четыре роли, организации, ограничения доступа на сервере, кампании и назначения одному ответственному эксперту.
- Создание сотрудников, CSV/XLSX-импорт, временные пароли для ручной передачи, обязательная смена, сброс администратором, блокировка, согласие и аудит.
- Русский и казахский интерфейс и 444 вопроса в шести направлениях, включая 220 матриц OMIB, расширенные блоки вербального (16), числового (52) и ситуационного (16) мышления. Дополнительные вопросы AssessFlow отделены в документации от исходных форм и требуют методологической проверки.
- Пять типов вопросов; сохранение каждого ответа, восстановление попытки, контроль конфликтов вкладок, защита от повторной отправки. Ключи остаются на сервере.
- Серверный расчёт когнитивных тестов, 5 факторов / 30 фасет IPIP, 6 шкал WMPS и предварительного SJT 0–32. Старые ответы и расчёты сохраняются.
- Конструктор пяти упражнений: компетенции, индикаторы, редактируемая шкала, «Не наблюдалось», комментарии, материалы и версии наблюдений.
- Экспертное заключение, план развития, ручная 9-box с обязательным обоснованием и настройкой осей, история версий.
- Таблицы сотрудников, фильтры, сопоставление одинаковых версий, Excel, индивидуальный PDF минимум 4 содержательных раздела на отдельных страницах и командный PDF.
- OpenRouter: очередь, повторы, JSON-схема, ссылки на основания, обезличенный ID, версии промпта, согласованные провайдеры, ZDR, учёт токенов и бюджета. Ключ задаётся в панели владельца и шифруется на сервере либо читается из окружения.

## Индивидуальные и командные AI-отчёты

В кабинете администратора доступны **«Отчёты»** (`/reports`) и **«Командные отчёты»** (`/team-reports`). Выберите кампанию и язык в верхней панели, затем нажмите «Сформировать». Для индивидуального отчёта участник должен завершить назначенные тесты; командный отчёт использует уже рассчитанные результаты и показывает неполноту данных.

Формирование идёт в фоне через OpenRouter и отдельную очередь BullMQ `assessflow-reports`. Статус обновляется автоматически. После завершения доступны просмотр и скачивание PDF А4, без обязательного экспертного утверждения. Эксперт видит готовые отчёты по назначенным ему участникам; командный файл доступен ему, если все участники этого файла назначены ему. Существующее экспертное заключение сохраняется отдельно.

PDF включает профили и числовые значения, выводы, сильные стороны, риски, рекомендации и план развития с предложенными сроками и критериями прогресса. В индивидуальном отчёте пять содержательных тематических разделов помимо титула и приложения; длинные разделы распределяются по дополнительным страницам. Командный отчёт содержит сравнение подразделений и размеры выборок. Матрица 9-box не включается в PDF; в отчётах также не показываются счётчики практических упражнений и поясняющие заглушки об отсутствующих оценках.

Каждая генерация сохраняет снимок исходных данных, язык, промпт, модель и расходы. Повторное формирование создаёт новую версию; готовые файлы остаются в истории. Владелец видит расход обоих типов AI-отчётов в общей истории генераций. Для обновления существующей установки необходимы миграции, включая `202610230003_default_ai_prompt_version` (`npm run db:migrate`).

Локальная проверка настоящего OpenRouter и создание примеров на вымышленных данных (использует настроенный ключ и расходует бюджет):

```powershell
npx tsx scripts/generate-report-samples.ts
# Отдельно казахский индивидуальный отчёт:
npx tsx scripts/generate-report-samples.ts --language=kk --kind=individual
```

Результаты сохраняются в `output/pdf/`, который исключён из Git. Скрипт доступен только при `DEMO_MODE=true` и использует готовый отчёт повторно, если исходные данные не изменились.

## Проверки

```powershell
npm test
npm run typecheck
npm run build
# При запущенных API и web:
$env:TEST_PDF='true'
$env:TEST_LOAD='true'
npm run test:integration
```

Интеграционная проверка создаёт собственную временную организацию и удаляет только свои записи. Проверены 444 двуязычных ответа, роли, подмена организации, сессии, согласие, автосохранение, таймер и повторная попытка, критерии, заключения, выгрузки, доступ к новым AI-отчётам и удаление содержащих участника снимков. При `TEST_PDF=true` проверяются PDF и частное S3-хранилище; при `TEST_LOAD=true` включается дополнительная проверка 30 одновременных прохождений. Артефакты — `artifacts/`.

## Перед использованием с реальными сотрудниками

В локальной среде проверена реальная генерация индивидуального и командного отчётов через OpenRouter. Для другой установки необходимо отдельно настроить ключ, модель, разрешённых провайдеров и бюджет. Без ключа тестирование и экспертная работа доступны, а формирование AI-отчётов сообщает об отсутствии настройки.

Методологические границы и источники подробно описаны в [SOURCES.md](SOURCES.md). В production все поставляемые формы первоначально создаются черновиками. Для публикации требуется указать утверждающего, подтвердить переводы и права. OMIB в этой версии — явно обозначенная техническая адаптация под выбор изображения; её нельзя считать утверждённой оригинальной формой.

Инструкции VPS, резервных копий и безопасного первого входа: [DEPLOYMENT.md](DEPLOYMENT.md). Оставшиеся ограничения и границы проверки: [ACCEPTANCE.md](ACCEPTANCE.md).
