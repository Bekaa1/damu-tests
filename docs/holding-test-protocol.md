# Холдинг: локальная синтетическая демонстрация и браузерный протокол

## Границы

Только loopback и БД `assessflow_holding_YYYYMMDD[_suffix]`. Допустим только параметр `schema=public`; подмена host и другие параметры запрещены. Удалённого/production override нет. `.env` не выводить. Внешний AI должен быть отключён серверной политикой; браузер дополнительно блокирует внешние адреса.

Организация `holding-synthetic-demo-20261121`: **«Демонстрация — вымышленные данные»**, `purpose=assessment`, `dataMode=synthetic`. Это не pilot: локальный PDF по данным должен оставаться доступным. Не трогает существующие `demo-organization`, pilot и рабочие аккаунты.

## Подготовка родительской интеграции

1. Применить parent-owned миграцию Holding и выполнить `prisma generate`.
2. Установить шесть канонических форм из `data/catalog.json` (draft допустим).
3. Подготовка вызывает parent-owned `installHoldingKey(db,{apply:true,actorId,reason})` из `scripts/install-holding-key.ts`: append-only Holding-версия ключа `situations-v2`, без изменения старого ключа. Только уже установленные канонические draft-формы публикуются локально с `approvedBy=DEMO_ONLY`, `approvedAt=null` и синтетической provenance; это не методологическое утверждение.
4. Родитель запускает ровно один локальный API на `127.0.0.1:4301` и web на `localhost:3301`. Скрипты не запускают свои серверы.

```bash
npx vitest run tests/holding-demo.test.ts
npx tsx scripts/prepare-holding-demo.ts
BASE_URL=http://localhost:3301 npx tsx tests/holding-browser-protocol.ts
```

Только командный RU-образец без заявления о браузерной приёмке:

```bash
BASE_URL=http://localhost:3301 npx tsx tests/holding-browser-protocol.ts --sample-only
```

Короткая проверка именно разграничения прав и cleanup оператора, **без** повторного создания fixtures, прохождения тестов, выпуска PDF или изменения ключей/результатов:

```bash
BASE_URL=http://localhost:3301 npx tsx tests/holding-browser-protocol.ts --operator-smoke-only
```

Она использует уже подготовленную synthetic-организацию, проверяет реальный 403 для demo key reviewer и реальный 200 с непустой методикой для временного system operator. Итог `operator_smoke_only` не равен приёмке шести форм: все 48 ячеек остаются `not_tested`. Указатель артефакта — `operator-smoke-latest.json`; основной `latest.json` не перезаписывается.

## Данные и идемпотентность

- 65 уникальных **выдуманных** имён `Демо-участник 01` … `65`, ID и адреса `holding-demo-participant-XX@example.invalid`.
- Все участники связаны с исходным `profileRow`; строки 55/56 и 58/59 остаются разными людьми. Из профиля копируются только номер, блок, подразделение, должность и целевой буквенный уровень. Имена, emails и ответы исходных людей не читаются.
- Отдельные пользователи `holding-demo-admin`, `holding-demo-expert`. Существующий `holding-demo-key-reviewer` сохраняется без изменения учётных данных и флага `platformAdmin=true`, но при `demoOnly=true` этот флаг **не даёт** платформенный доступ: чтение методики и recalculation обязаны вернуть 403. Это отрицательный контроль защиты, а не рабочий superadmin.
- Для versioned recalculation браузерный протокол создаёт **нового временного LOCAL SYSTEM OPERATOR** `${runId}-local-operator`: `demoOnly=false`, `platformAdmin=true`, без членства в демонстрационной организации. Это явно синтетический локальный тестовый механизм, **не часть demo/Fund-доступа**. Только fresh create, без upsert/усыновления существующего пользователя. Пароль случайный, существует только в памяти процесса; в protected demo credentials ничего не добавляется. В `finally` выполняются logout, закрытие контекста, отзыв точных сессий и удаление только этого run-owned пользователя/его auth-записей с readback нулевых остатков. Создание/удаление сохраняются в audit с test provenance.
- Случайные локальные пароли генерируются программно, хранятся вне Git с правами `0600` в `/root/research/damu-tests/implementation/demo/.local-credentials.json`, не печатаются и не снимаются на скриншотах.
- Основная кампания: Казахстан, 21.11.2026–20.01.2027. 390 явно синтетических результатов (65 × 6), с `reason=synthetic_generated_fixture_not_browser`, `provenance.browserVerified=false`, `timerVerified=false`, `simulatedResponseDurations=true`.
- Результаты действительно рассчитываются установленными ключами, K1=2/K2=4, ranking 3+3 без пересечения. Флаги качества вычисляются штатным алгоритмом и не подменяются.
- Существующие попытки никогда не удаляются/не сбрасываются; повторная подготовка не меняет историю. Конфликт namespace, привилегий, ролей, профилей или маркировки — ошибка, не «исправление» чужого объекта.
- Образец не создаёт экспертных наблюдений, согласованных заключений, 9-box или национальных норм. 65 синтетических завершений пригодны для отдельной технической проверки frozen norm, но не являются референтной выборкой реальных людей.

## Восемь измерений × шесть форм

Каждый запуск создаёт отдельную браузерную кампанию и новые назначения для одного из 65 synthetic-only участников. Не сбрасывает основной демонстрационный результат. Все основные ответы вводятся через настоящие видимые браузерные элементы.

1. Четыре timed-формы: видимая исходная интерактивная тренировка до старта; до нажатия «Начать тест» `timerStartedAt=null`. Для personality/motivation источник `data/catalog.json` явно задаёт `delivery.practice=[]` и `timeLimitSeconds=null`: только после проверки этих исходных значений, пустой installed practice и отсутствия deadline до/после настоящего старта ячейка интерактивной тренировки получает **not_applicable** с точной source reason, не pass. Неизвестное/неподтверждённое отсутствие тренировки остаётся partial. Инструкция, сохранение, завершение, recalculation и PDF для этих двух форм по-прежнему проверяются полностью.
2. Старт таймера/безлимитность: verbal 1320, numerical 1500, logical 1200, SJT 1800 секунд; personality/motivation без deadline.
3. Настоящий ввод, серверное сохранение, перезагрузка и продолжение с прежним сроком.
4. `BrowserContext.setOffline(true)`, новый ответ в локальной очереди, отсутствие его на сервере, reconnect, автоматическая отправка и очистка очереди; deadline не продлевается.
5. Ручное завершение через UI. Для четырёх timed-форм дополнительно отдельная попытка с ускоренным сроком: **deadline advanced in synthetic fixture**, не «ждали 20 минут». Нулевой набор должен честно стать `retry_required`, причина audit — `deadline`.
6. Время готовности реального результата относительно фактического завершения и его ключ. Быстрые автоматические ответы могут честно получить флаги качества.
7. Настоящий RU PDF участника после завершения всей батареи: фиксируются server `readyAt`, время от каждой формы и отдельно от последней формы. PDF из 65 DB-fixtures не подставляется вместо этого доказательства.
8. Администратор видит участника; обычному администратору и существующему `demoOnly` key reviewer recalculation запрещён (403). Только временный run-owned LOCAL SYSTEM OPERATOR создаёт новую версию с **тем же** config через штатный API и контрольный пример и выполняет recalculation. Readback подтверждает новую result/key version и неизменность старых результатов. Эти append-only версии остаются только в локальной тестовой БД; оператор и его auth-записи удаляются в `finally`. Backend privacy/role guard не изменяется и не обходится demo-учётной записью.

## Артефакты и честный статус

- `/root/research/damu-tests/implementation/demo/fixture.json` — readback подготовленных данных.
- `/root/research/damu-tests/implementation/demo/Холдинг-синтетический-командный-образец-ru.pdf` — реальный data-only образец из 65 synthetic результатов.
- `/root/research/damu-tests/implementation/timer-protocol/latest.json` указывает на уникальный каталог запуска.
- `matrix.json`: все 48 ячеек, `pass/not_applicable/partial/fail/blocked/not_tested`, фактические времена, серверные ID, API-статусы, пути настоящих PNG. N/A считается отдельно от pass и допустим только в training-ячейках двух указанных untimed-форм при подтверждённом source exemption; «48 passes» не подставляется вместо реальных счётчиков.
- `observations.localSystemOperatorCleanup` подтверждает logout и отсутствие run-owned user/account/session/membership после завершения; `protectedDemoCredentials.unchanged=true` проверяется по SHA-256 файла до/после, без вывода содержимого.
- Любой readiness blocker сохраняется в JSON; скрипт не ждёт сервисы бесконечно и ничего не выдумывает. `partial/blocked` возвращает exit 1. Отсутствующий PDF не считается созданным только потому, что его предполагаемый путь напечатан.
- Сгенерированный PDF нужно отрендерить (например `pdftoppm -png`) и визуально осмотреть страницы перед передачей. Содержимое синтетического образца не является полным интегрированным отчётом с наблюдением/интервью/экспертным заключением.
