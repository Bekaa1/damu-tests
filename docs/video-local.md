# Видеозапись тестов на локальном стенде

Функция включается парой `VIDEO_ORGANIZATION_ID` и `VIDEO_CAMPAIGN_ID`. Для локальной проверки используйте отдельную базу с синтетическими участниками. Команда `npm run db:migrate` добавляет поля согласия и таблицу подключений. Остальные кампании работают по своим обычным правилам.

## Запуск

Понадобятся Docker Compose и запущенные API, веб-приложение и PostgreSQL. Добавьте в локальный `.env`:

```dotenv
VIDEO_ORGANIZATION_ID=demo-organization
VIDEO_CAMPAIGN_ID=demo-campaign
LIVEKIT_API_KEY=video-dev
LIVEKIT_API_SECRET=<случайный секрет длиной не менее 32 символов>
LIVEKIT_URL=http://127.0.0.1:7880
LIVEKIT_PUBLIC_URL=ws://localhost:7880
LIVEKIT_NODE_IP=<локальный IPv4 компьютера, доступный браузеру и Docker>
VIDEO_RECORDINGS_DIR=./.data/video-recordings
```

Запустите `docker compose -f compose.video.yml up -d`, затем API и веб-приложение из корня проекта. Если приложение уже запущено, перечитайте настройки перезапуском API. Сигнализация на стенде доступна через localhost, медиатрафик использует TCP 7881 или UDP 7882. При изменении адреса компьютера обновите `LIVEKIT_NODE_IP` и пересоздайте медиасервисы. Записи в каталоге хоста должны быть доступны для записи контейнеру Egress и для чтения и удаления API.

## Проверка

1. Войдите под участником с назначением в выбранной кампании. При первом входе примите согласие на видео, затем обычное согласие на данные, если оно ещё не принято.
2. Пройдите тренировку, нажмите «Начать тест», затем «Подключить камеру». После разрешения браузера дождитесь надписи «Идёт видеозапись». Сервер запускает новую попытку отсчёта времени после подтверждения записи. При возврате в уже запущенную попытку сохраняется исходный срок сдачи.
3. В другом профиле браузера войдите под администратором той же организации, выберите ту же кампанию и откройте «Видеозаписи». Нажмите «Смотреть эфир». Руководитель может выбрать участника по имени и тесту.
4. Выйдите из теста. Когда сервер закроет файл, в архиве появится «Скачать запись». Ссылка требует входа руководителя. Повторное подключение создаёт отдельный фрагмент с собственным временем и сроком хранения. Дата истечения видна в таблице. Временные файлы, прерванные задания и истёкшие записи обрабатываются фоновым процессом API.
5. Для проверки состава файла выполните `ffprobe -v error -show_entries stream=codec_type,codec_name -of json <файл.webm>`. В файле должен быть один видеопоток VP8. Дата, редакция, язык и принятый текст доступны в событии журнала `video.consent`.

Браузер отправляет только видео с камеры. LiveKit передаёт поток администратору, а Track Egress сохраняет его на диск без перекодирования. При потере связи интерфейс предлагает переподключить камеру. Ответы сохраняются обычным механизмом теста, отсчёт времени продолжается. Архив платформы удаляет видео через три календарных месяца после окончания каждого фрагмента. Скачанные администратором копии хранятся отдельно от платформы.

Для эксплуатации потребуется проверить одновременные записи на выбранных серверах в Казахстане, закрытый каталог с достаточным местом, HTTPS/WSS и доступность медиатрафика из сети заказчика. Локальная конфигурация рассчитана на проверку функциональности.
